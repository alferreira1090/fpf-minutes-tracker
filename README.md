# FPF Minutos

Web app and JSON API that turn saved **FPF match-report pages** (Centro de Resultados, HTML) into per-player
**minutes, call-ups, appearances, goals and yellow cards**, per league and globally, plus two club utilization
indicators. It is the web version of the Excel tracker produced by the `fpf-player-match-tracker` skill and applies
the same rules (stoppage time, half-time substitutions, dismissals, per-match duration corrections, call-up evidence
for unused substitutes, pooled indicators).

> **Personal data warning.** Match pages and the database contain names of minors. `data/` is git-ignored, the server
> binds to `127.0.0.1` by default and there is **no authentication yet**. Do not expose it to a network before the
> authentication change is done (see `openspec/`).

## Run

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
fpf-tracker                      # http://127.0.0.1:8000  (API docs: /api/docs)
```

1. Create a club (name as it appears on the FPF site, e.g. `Fc Famalicão`).
2. *Carregar jogos*: drop one or many saved FPF pages. Re-uploading the same match updates it (matched by FPF match id).
3. Open the league views, *Resumo global*, *Jogos* (per-match audit and duration correction) and *Identidades*.

Environment: `FPF_DATA_DIR` (default `data`), `FPF_HOST` (default `127.0.0.1`), `FPF_PORT` (default `8000`).
Try it without real data: `python scripts/seed_demo.py data-demo && FPF_DATA_DIR=data-demo fpf-tracker`.

## Test

```bash
pytest
```

Test pages are generated by `tests/fpf_fixture.py` with invented names, mirroring the FPF markup.
Hand-checked scenario: a 93-minute match whose players sum to 11 × 93 = 1023 minutes, including a name that appears
in both squads.

## How it is built (OpenSpec-driven)

Behaviour is specified first with [OpenSpec](https://github.com/Fission-AI/OpenSpec) (`npm i -g @fission-ai/openspec`):

```
openspec/
  specs/                 # current truth, one folder per capability (filled when a change is archived)
  changes/<name>/        # proposed changes: proposal.md, specs/ (deltas), design.md, tasks.md
  changes/archive/       # finished changes
```

Workflow for every new feature: `openspec new change <name>` → write proposal, spec deltas, design, tasks →
`openspec validate <name> --strict` → implement the tasks (with tests) → `openspec archive <name>`.
Claude Code skills for this workflow are in `.claude/skills/` (`/openspec-propose`, `/openspec-apply-change`, …).
The first change is `add-fpf-match-ingestion-and-dashboard`.

## Layout

```
src/fpf_tracker/
  domain/     pure logic: parser.py, minutes.py, identity.py, metrics.py   (no I/O, heavily tested)
  storage/    SQLite schema and queries
  services/   ingest orchestration (parse -> compute -> identity -> store)
  web/        FastAPI app, pt-PT templates, static assets
tests/        unit, service and web tests
scripts/      seed_demo.py (synthetic demo data)
```

## Known limits (v0.1)

- No authentication or roles; localhost only. No Excel export. Identity merges cannot be edited by hand yet.
- The FPF player id taken from the lineup photo URL is assumed stable across matches; the *Identidades* page lists every
  merge made by name only, and every homonym, so this can be checked against real data.
- Fonts are loaded from Google Fonts; self-host them before any hosted deployment.
